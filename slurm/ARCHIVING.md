# Job Archiving System

## Overview
All `run_*.sh` scripts now automatically archive job outputs to `prev_execs/` after completion.

## How It Works
When you run any `run_*.sh` script, it will:
1. Clean up old files (m_log, forces.0.dat, Residual)
2. Submit your main SLURM job
3. Automatically submit an archive job that waits for the main job to complete
4. Auto-detect the job description from `custom_logs/*_{JOB_ID}.log` files
5. Archive the following files to `prev_execs/{JOB_DESC}_{JOB_ID}/`:
   - `custom_logs/{JOB_DESC}_{JOB_ID}.csv`
   - `custom_logs/{JOB_DESC}_{JOB_ID}.log`
   - `logs/error.{JOB_ID}.txt`
   - `logs/output.{JOB_ID}.txt`
   - `forces.0.dat`
   - `m_log`
   - `Residual`

## Auto-Detection
The job description is automatically detected from your custom_logs files based on the naming pattern:
```
{NODES}x{TASKS_PER_NODE}={NTASKS}_{PARTITION}_{NODELIST}_{JOB_ID}
```

This pattern is generated by the C++ logger (logger.hpp) using SLURM environment variables, so no manual configuration is needed!

## Monitoring
After submitting, you'll see output like:
```
Main job submitted: 64991271
Archive job submitted: 64991272
Monitor with: squeue -u ro092286
```

The archive job will only run after the main job completes successfully (`afterok` dependency).

## Manual Archiving
If you need to archive an already-completed job manually:
```bash
sbatch slurm/archive_job.sh JOB_ID
```

Example:
```bash
sbatch slurm/archive_job.sh 64991271
```

The job description will be auto-detected from the custom_logs files.

## Archive Location
All archived jobs are stored in: `prev_execs/{JOB_DESC}_{JOB_ID}/`

Example:
```
prev_execs/1x24=24_devel_n23m0123_64991271/
├── 1x24=24_devel_n23m0123_64991271.csv
├── 1x24=24_devel_n23m0123_64991271.log
├── error.64991271.txt
├── forces.0.dat
├── m_log
├── output.64991271.txt
└── Residual
```
